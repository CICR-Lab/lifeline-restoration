# Module 02 - Emergent Simplicity

## 1. Overview

This module implements the emergent-simplicity analysis of post-earthquake
lifeline restoration. It supports Figure 3, Supplementary Figures 6-12,
Supplementary Tables S3-S7 and the empirical source data used by Module 03.
The analysis prepares eligible restoration trajectories, fits restoration-shape models,
quantifies loss compression and late loss, and evaluates cross-lifeline timing and
coupling. It uses the external canonical dataset placed in Module 00.

The module separates analysis workflows from public plotting workflows. The
plotting workflows can read either retained files under `figure_data/` or
figure inputs generated by the analysis workflows under `outputs/figure_data/`.

## 2. Requirements

- MATLAB with Optimization Toolbox for restoration-shape fitting with
  `lsqcurvefit`.
- Statistics and Machine Learning Toolbox for the supplementary contextual-
  stability analysis.
- The canonical input `../00_Dataset/standardized_dataset.mat` for analysis
  workflows. Request access at <https://doi.org/10.5281/zenodo.23113551>; after
  approval from the authors, download the MAT file and place it in Module 00.
- The confirmed manual exception-class interface stored in `Code/` for the
  supplementary analysis workflow.

## 3. Inputs

### Upstream input

```text
../00_Dataset/standardized_dataset.mat
```

This is the canonical dataset used by the analysis workflows to prepare the
restoration trajectories and the three principal analysis branches. Follow
the Module 00 README for the Zenodo access request and authorized download.
Figure-only rendering with `DataSource="packaged"` reads the direct inputs in
`figure_data/main/` and `figure_data/supplementary/`.

### Manual classification input

```text
Code/exception_classes.xlsx
```

The `FigS9_S11_exceptions` sheet records the confirmed classifications for the
exception trajectories. Required fields are `record_ID` and
`exceptionClass`; `plotOrder` is optional. The workbook is maintained by the
researcher as the classification input.

The fitting code produces candidate rows and associated fit statistics. The
researcher reviews those outputs using the criteria below and enters the labels
in `Code/exception_classes.xlsx`. The supplementary analysis reads that
workbook when assembling the exception source data.

## 5. Running the module

Run the public entries from the `02_EmergentSimplicity` directory.

### Main analysis

```matlab
run_emergent_simplicity_analysis()
```

This runs the restoration-shape, loss-compression and cross-lifeline timing
analyses and writes regenerable intermediate results and a combined Figure 3
source-data workbook under `outputs/figure_data/main/`. The supplied Figure 3
workbook is stored in `figure_data/main/`.

### Figure 3

```matlab
run_figure_3("DataSource", "packaged")
```

This entry point reads only the selected Figure 3 source workbook and writes
Figure 3 to `outputs/figures/main/`. To check the complete analysis-to-figure
data chain after running the analysis, use:

```matlab
run_figure_3("DataSource", "generated")
```

The generated source is `outputs/figure_data/main/SourceData_Figure3.xlsx`.
A separate output directory can be supplied for validation, for example:

```matlab
run_figure_3(fullfile(tempdir, "emergent_simplicity_figure3"))
```

`DataRoot` can be supplied when the selected direct figure-data folder is
stored elsewhere.

### Supplementary analysis and tables

```matlab
run_supplementary_emergent_simplicity_analysis()
```

This runs the supplementary calculations and writes the regenerable Supplementary Table
S3-S7 source workbooks and analysis intermediates under `outputs/`.

The exception-trajectory workflow is:

1. the main fitting code generates
   `outputs/intermediate/01_restoration_shape_phase_ratio/badfit_weibull_gompertz_loglogistic_ge6_candidates.xlsx`
   (sheet `badfit_candidates`) and the corresponding trajectory and fitted-model
   results in `unique3_records.mat` and `restoration_shape_ge5_fit_result.mat`
   in the same directory;
2. the researcher checks the candidate record IDs, observed trajectories,
   observation timing, fitted curves and model MAEs in these outputs, using the
   empirical criteria below;
3. the confirmed labels are entered in the
   `Code/exception_classes.xlsx` interface;
4. the supplementary analysis reads that workbook and assembles the exception
   source data.

Candidates in the main analysis have at least six observations. The Weibull,
Gompertz and log-logistic models must all have converged, with finite MAEs
that all exceed the adequacy threshold of 0.05. The retained candidate and
fit files in `figure_data/supplementary/` can also be inspected without
rerunning the main analysis. The fit file
`restoration_shape_ge5_fit_result.mat` includes fits used for temporal-resolution
sensitivity.

Classification follows Supplementary Note S3.1 in the final manuscript:

| Empirical group | Internal label in the workbook | Observed classification features |
|---|---|---|
| Late-stage recovery constraints | `Long tail` | Sustained slow or stalled recovery beyond a recovery stage. |
| Limited temporal resolution | `Near threshold` | Trajectories near the minimum temporal-resolution threshold that become adequate under the relaxed criterion MAE <= 0.07. Sparse observation timing limits assessment of curve shape. |
| Unknown | `Unknown` | Irregular fluctuations or multistage recovery. |

These are researcher-assigned empirical groups based on observed trajectories
and fitted-model results. The table above describes their classification
features. Difficult-to-repair components, inaccessible areas, reconstruction
needs, changing service demand, secondary hazards, strategy changes and
inconsistent reporting are possible mechanistic interpretations of those
features.

### Supplementary figures

```matlab
run_supplementary_emergent_simplicity("DataSource", "packaged")
```

This is the figure-only entry point. It reads only the selected retained or
generated files and writes Supplementary Figures 6-12 to
`outputs/figures/supplementary/`. To use the direct outputs of the
supplementary analysis, run:

```matlab
run_supplementary_emergent_simplicity("DataSource", "generated")
```

The generated supplementary figure-data files are collected under
`outputs/figure_data/supplementary/`. Each plotting call uses the single source
selected by `DataSource`.

## 7. Reproducibility notes

- Random-number seeds are fixed in the relevant analysis scripts; the main
  loss-compression bootstrap uses 2,000 resamples.
- Manual exception classifications are stored in
  `Code/exception_classes.xlsx` and are checked against the candidate record
  IDs during the supplementary analysis.
- The three exception groups are researcher-assigned empirical classifications
  based on observed trajectories and fitted-model results.
- The `Long tail` and `Near threshold` labels are the internal labels used by
the code for the manuscript descriptions of late-stage recovery
  constraints and limited temporal resolution, respectively.
- The plotting entries are independent of generated analysis outputs when
  `DataSource="packaged"` is selected. The `generated` option requires the
  corresponding analysis workflow to have produced the selected figure data.
- Re-run the analysis workflows if the authorized canonical dataset or the manual
  classification interface changes. Re-run the plotting workflows when only a
  figure export is needed.
